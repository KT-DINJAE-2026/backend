# 백엔드 발표 자료

## 9. 방법론 – 재차인원 복원

### 데이터 처리 규모

- 2025년 4월 서초구 TCD 원본 30일, 약 11.8GB 처리
- 마을·간선·지선버스 탑승 기록 9,549,276건
- 서초구 TCD에 포함된 87개 노선, 281,993개 운행회차 복원

### 운행회차 분리

- 동일 차량·노선의 승차 태그를 시간순으로 정렬
- 작은 순번 변동은 허용하고, 현재 회차의 최대 정류장 순번보다 3개를 초과해 기점 방향으로 돌아가면 새로운 운행회차로 분리
- 순번 역행을 확인하지 못하더라도 직전 승차 태그와 60분 이상 차이가 나면 새로운 운행회차로 분리
- 각 회차 안에서 승·하차 인원을 누적하여 정류장 구간별 재차인원 복원

### 기술적 난관

- 원본의 운행출발일시가 일부 차량에서 하루 종일 동일하게 기록되는 문제 발견
- 서초구 4월 1일 기준 분석 대상 차량 1,693대 중 62대에서 운행출발일시가 하나의 값으로만 기록됨
- 운행출발일시만으로 회차를 구분할 경우 서로 다른 운행이 하나로 합쳐져 한 회차에 1,000건 이상, 최대 1,063건의 승차 기록이 포함되는 오류 발생
- 원본 운행출발일시 대신 정류장 순서와 회차별 첫 승차시각을 조합해 운행회차를 추정

## 10. 방법론 – 좌석 배정 시뮬레이션

### 승객 단위 FIFO 좌석 배정

1. 운행회차별 승차·하차 이벤트를 시간순으로 정렬
2. 빈 좌석이 있으면 착석시키고, 좌석이 모두 차면 입석 대기열에 배정
3. 착석 승객이 하차하면 가장 먼저 입석한 승객을 우선 착석
4. 입석 시작부터 최초 착석 또는 입석 상태로 하차할 때까지의 시간을 입석시간으로 계산

### 좌석 수 가정

- 마을버스: 20석
- 간선·지선버스: 25석
- 실제 차량별 좌석 수가 아닌 버스 유형별 대표 좌석 수를 적용

### 동일 시각 처리

- 동일 시각에는 하차 이벤트를 승차 이벤트보다 먼저 처리
- 동일 시각의 같은 종류 이벤트는 고정된 난수 시드를 사용해 순서를 결정
- 같은 원본 데이터와 같은 코드에서는 동일한 결과가 나오도록 재현성 확보

### 한계

- 실제 좌석 센서가 없어 버스 유형별 대표 좌석 수를 적용
- 좌석 양보, 승객의 자발적 입석, 좌석 선호 등을 반영하지 못함
- 교통카드 탑승 기록 한 건을 승객 한 명의 한 번 탑승으로 가정
- 하차 미태그 승객은 운행회차 종료까지 탑승한 것으로 처리
- 서초구 밖에서 승·하차한 기록이 누락되면 여러 자치구를 지나는 노선의 재차인원이 실제보다 낮게 복원될 수 있음
- 산출된 입석 여부와 입석시간은 실측값이 아니라 시뮬레이션 추정값

### 방어 논리

- FIFO는 특정 승객을 임의로 선택하지 않고 먼저 입석한 승객에게 먼저 좌석을 배정하는 일관된 기준
- 하차 미태그 승객을 회차 종료까지 재차인원에 포함하여 해당 결측이 재차인원을 과도하게 낮추지 않도록 처리
- 고정된 난수 시드를 사용하여 같은 원본 데이터에서 결과를 재현할 수 있음
- 모든 데이터에 동일한 규칙을 적용하여 일관되고 재현 가능한 모델 학습용 추정 레이블을 생성
- 현재 결과를 실측 입석 정보가 아닌 입석 위험의 추정값으로 안내
- 향후 실제 차량별 좌석 수와 입석 실측 자료를 확보하면 시뮬레이션을 보정할 수 있음

## 12. 결과 – 입석 실태

### 분석 데이터

- 2025년 4월 서초구 제공 TCD에 포함된 마을·간선·지선버스 탑승 기록 9,549,276건 분석
- 착석 추정: 8,608,356건
- 입석 추정: 940,920건
- 전체 승차 시점 입석률: 9.85%

### 교통약자 입석 현황

- TCD에서 식별 가능한 어린이·경로·장애인을 교통약자 대리집단으로 정의
- 교통약자 대리집단의 전체 탑승 기록: 516,691건
- 이 중 입석으로 추정된 기록: 40,504건
- 교통약자 대리집단의 입석률: 7.84%
- 전체 입석 사례에서 교통약자 대리집단이 차지하는 비중: 4.30%
- 임산부, 영유아 동반자, 일시적 보행 장애 등은 교통카드 코드로 식별되지 않으므로 실제 교통약자 규모는 더 클 수 있음

### 시간대별 입석률

- 출근 시간인 8시 입석률: 24.55%
- 퇴근 시간인 18시 입석률: 22.26%
- 7시 입석률: 15.99%
- 17시 입석률: 15.49%
- 출퇴근 시간대에 입석 위험이 뚜렷하게 집중됨

### 입석시간 분석

- 전체 입석 추정 기록 940,920건 중 입석시간을 확인할 수 있는 940,892건 분석
- 하차 미태그로 입석시간을 확정할 수 없는 28건은 시간 분석에서 제외
- 평균 입석시간: 344초, 약 5분 44초
- 중앙 입석시간: 265초, 약 4분 25초
- 입석시간 상위 10%의 경계: 723초, 약 12분 3초

### 입석시간 구간별 비율

- 5분 이하: 523,537건, 55.64%
- 5분 초과~10분 이하: 273,558건, 29.07%
- 10분 초과: 143,797건, 15.28%
- 전체 입석 사례의 44.36%가 5분을 초과해 입석

### 결과 해석

- 전체 탑승 사례 약 10건 중 1건이 승차 시점에 입석한 것으로 추정됨
- 출퇴근 시간대에는 탑승 사례 약 4~5건 중 1건이 입석한 것으로 추정됨
- 입석 탑승 사례 약 6~7건 중 1건은 10분을 초과해 입석
- 교통약자가 버스를 타기 전에 입석 위험이 낮은 차량을 선택할 수 있도록 정보를 제공할 필요성을 확인

> 교통카드 승하차 기록과 버스 유형별 대표 좌석 수를 이용한 FIFO 좌석 배정 시뮬레이션 추정치이며, 실제 좌석 센서 측정값은 아님.

## 17. 시스템 구성

### 시스템 분리 구조

```text
정류장 QR
→ React 웹 프론트엔드
→ Spring Boot API 서버
→ 정류장·노선 데이터베이스, 실시간 버스 도착정보 API, 날씨 API, AI 예측 모델
→ 도착시간·입석 위험·예상 착석 시점 반환
```

### React 프론트엔드

- QR을 통한 출발 정류장 진입
- 목적지 검색과 로드뷰 제공
- 출발지와 목적지를 잇는 직통 버스 비교
- 직통 노선별 도착 예정 차량을 최대 2대까지 표시
- 차량별 도착시간, 저상버스 여부, 입석 위험과 예상 착석 시점 표시
- 백엔드가 제공한 수치와 상태값을 사용자가 이해하기 쉬운 문장으로 변환

### Spring Boot API 서버

- QR 출발 정류장 정보 제공
- 목적지 정류장 검색
- 출발지와 목적지를 정방향으로 함께 지나는 직통 노선 판정
- 실시간 버스 도착정보 조회
- 모든 직통 노선에서 TOPIS가 ETA를 제공하는 첫·두 번째 차량을 최대 2대까지 선별
- 예측 시각, 요일, 공휴일, 날씨, 배차간격 등 AI 모델 입력값 생성
- 차량별 입석 여부와 입석시간 예측
- AI 예측 결과를 입석 위험도와 예상 착석 시점으로 변환
- 최종 결과를 JSON 형식으로 React에 전달

### 데이터베이스

- 정류장 ID, ARS 번호, 정류장명, 위도·경도 저장
- 노선 정보와 정류장 경유 순서 저장
- 출발 정류장보다 뒤에 목적지 정류장이 있는 노선을 직통 노선으로 판정
- 운영 환경에서는 MySQL을 사용하고 시연·테스트 환경에서는 H2 데이터베이스 사용

### 실시간 차량 조회

1. 사용자가 출발·도착 정류장을 선택하면 백엔드가 두 정류장을 정방향으로 함께 지나는 직통 노선 전체를 조회
2. 각 직통 노선 ID로 TOPIS 노선 전체 도착정보 API를 호출
3. 출발 정류장의 첫 번째·두 번째 도착 예정 차량을 노선별 최대 2대까지 선택
4. 모든 직통 노선을 유지하고, 각 차량의 도착시간과 입석 위험을 계산

### 도착 예정시간 계산

- 각 직통 노선의 첫 번째와 두 번째 차량에 TOPIS 도착정보 API의 공식 도착 예정시간을 사용
- 현재 도착 예정 차량이 두 대보다 적으면 실제 조회된 차량만 표시
- 세 번째 이후 차량의 ETA를 따로 추정하지 않음

### 실시간 API 처리 흐름

```text
서울시 버스도착정보 API
→ 모든 직통 노선의 노선 전체 도착정보 조회
→ 출발 정류장의 첫 번째·두 번째 차량 선택

백엔드
→ 차량별 AI 입석 위험 예측
→ 모든 직통 노선의 노선별 최대 2대 통합
→ 도착시간순 또는 입석 위험 추천순으로 정렬
→ React에 전달
```

### 외부 API 안정성 처리

- 동일 노선 전체 도착정보를 20초 동안 캐시하여 중복 호출 감소
- 연결 제한시간 3초, 전체 응답 제한시간 5초 적용
- 인증 실패, 통신 장애, 잘못된 응답 형식을 구분하여 처리
- 실시간 정보를 받을 수 없으면 서버 전체 오류와 구분하여 안내

### 화면에 표시되는 차량 범위

- 출발지와 목적지를 정방향으로 연결하는 직통 노선의 차량만 표시
- 각 직통 노선에서 TOPIS가 정확한 ETA를 제공하는 차량을 최대 2대까지 표시
- 전체 개수로 다시 잘라 특정 직통 노선을 누락시키지 않음
- 차량마다 별도의 식별값, 도착시간, 저상버스 여부와 입석 위험 결과 제공
