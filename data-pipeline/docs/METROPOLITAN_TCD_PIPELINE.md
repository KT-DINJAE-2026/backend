# KDATA METROPOLITAN TCD 전처리

## 1. 목적

`D:\20250328_KDATA`의 일별 ZIP을 변경하거나 압축 해제하지 않고 직접 읽어,
성북구 경유 버스의 승객 단위 입석 학습 명부를 생성합니다.

대상 TCD인 `TB_KTS_DWTCD_METROPOLITAN_YYYYMMDD.csv`는 헤더가 있는
18컬럼 CSV입니다. 차량·노선·승하차 정류장·승하차 시각·이용자 유형·이용자 수를
포함합니다.

## 2. 추출 범위

1. `STTN`에서 법정동코드가 `11290`으로 시작하는 버스 정류장을 찾습니다.
2. `ROUTESTTN`에서 위 정류장을 하나 이상 경유하는 버스 노선을 찾습니다.
3. TCD에서 선정 노선의 전체 승객을 읽습니다.
4. 교통수단코드가 `105`, `151`, `115`, `120`, `121`, `122`인 행만 사용합니다.

성북구 안에서 승하차한 행만 고르지 않습니다. 성북구 밖에서 먼저 탑승한 승객도
성북구 구간의 재차인원과 좌석 점유에 영향을 주기 때문입니다.

`이용자수`가 2 이상인 거래는 승객 수만큼 행을 확장합니다. 원본 가상카드번호는
중간 DataFrame과 출력 파일에 저장하지 않고, 원본 행 번호 기반 임시 식별값만 FIFO
처리에 사용합니다.

## 3. 실행

### 하루 파일럿

```powershell
python data-pipeline\build_metropolitan_roster.py `
  "D:\20250328_KDATA\DATA_20240401.zip" `
  "C:\bus-standing-work\pilot\roster_20240401.parquet" `
  --district-code 11290 `
  --standard-id-zip "D:\20250313_KDATA\DATA_20240401.zip" `
  --exclude-unmapped-standard-ids `
  --with-weather
```

### 여러 날짜

```powershell
python data-pipeline\build_metropolitan_batch.py `
  "D:\20250328_KDATA" `
  "C:\bus-standing-work\roster-2024" `
  --district-code 11290 `
  --standard-id-source-dir "D:\20250313_KDATA" `
  --exclude-unmapped-standard-ids `
  --with-weather `
  --date-from 20240101 `
  --date-to 20241231
```

검증된 기존 Parquet과 manifest가 있으면 건너뜁니다. 다시 만들려면
`--overwrite`를 추가합니다. 원본과 결과물은 대용량이므로 Git·OneDrive 저장 경로에
두지 않습니다.

일자별 파일 생성이 모두 끝나면 전체 학습기간 표본 수를 별도 디렉터리에 반영합니다.

```powershell
python data-pipeline\finalize_metropolitan_dataset.py `
  "C:\bus-standing-work\roster-2024" `
  "C:\bus-standing-work\roster-2024-final"
```

## 5. 처리 이력

각 Parquet 옆에 `.parquet.manifest.json`을 생성합니다.

- 파이프라인 버전
- 원본 ZIP 절대경로·크기·수정 시각
- 사용한 ZIP 항목의 CRC32와 압축 전후 크기
- 표준 ID 매핑 ZIP 경로·크기·수정 시각·항목 CRC32와 매핑 수
- 대상 법정동코드
- 선정 정류장·노선·행 수
- 결측·이상치 수
- 운행회차·차량·입석 결과

원본 ZIP은 읽기 모드로만 열며 manifest와 Parquet은 별도 출력 경로에 생성합니다.

## 6. 후속 처리 사항

### 6.1 ID 체계

18컬럼 TCD에는 정산사 노선·정류장 ID만 있으므로, 같은 날짜의
`D:\20250313_KDATA\DATA_YYYYMMDD.zip`에 있는 27컬럼 TCD를 ID 사전으로 함께 읽습니다.
27컬럼의 표준/정산 노선 ID와 표준/정산 승·하차 정류장 ID를 대응시켜 출력의
`route_id`, `board_stop_id`, `alight_stop_id`를 국토부 표준 ID로 변환합니다.

2024년 4월 1일 파일럿에서는 실제 사용된 노선 95개와 정류장 3,055개가 모두 매핑됐고
한 정산 ID가 여러 표준 ID를 가리키는 충돌은 0건이었습니다. 서로 다른 정산 ID가 같은
표준 ID를 가리키는 별칭은 정상적으로 하나로 통합합니다. 해당 날짜에 매핑 ZIP이 없거나
기본값에서는 필요한 ID가 하나라도 누락·충돌하면 결과를 만들지 않고 실패합니다.

실제 미정차·비표준 정류장처럼 표준 ID가 존재하지 않는 것으로 확인된 경우
`--exclude-unmapped-standard-ids`를 사용합니다. 해당 승객은 재차인원 복원과 FIFO
좌석 배정에는 포함해 다른 승객의 혼잡도에 미친 영향을 유지하고, 본인의 학습 출력 행만
제외합니다. 누락 ID 예시와 제외 행 수는 manifest에 기록합니다. 한 정산 ID가 여러 표준
ID를 가리키는 충돌은 이 옵션으로도 허용하지 않습니다.

`--standard-id-zip`을 생략하면 구조 확인용 복합 정산 ID를 사용할 수 있지만, 이 결과는
최종 AI 학습본으로 사용하지 않습니다.

### 6.2 전체 기간 표본 수

일자별 Parquet의 `sample_count_route_segment_hour`는 해당 하루 안에서 계산한 값입니다.
`finalize_metropolitan_dataset.py`는 일별 파일을 배치 단위로 두 번 순회합니다. 첫 번째
순회에서 임시 SQLite에 `(노선, 승차 정류장, 하차 정류장, 시간대)`별 전체기간 행 수를
누적하고, 두 번째 순회에서 각 파일의 표본 수 컬럼만 교체해 별도 출력 디렉터리에 씁니다.
따라서 전체 연도를 하나의 pandas DataFrame으로 합치지 않으며 입력 Parquet도 수정하지
않습니다.

2024년 4월 1일 1,043,593행 파일럿에서는 506,470개 그룹을 집계·재작성했고, 하루만
사용했으므로 모든 컬럼이 입력과 동일함을 확인했습니다. 두 날짜 합성 테스트에서는 같은
그룹의 일별 2건·3건이 양쪽 출력에서 전체기간 값 5건으로 바뀌는 것을 검증했습니다.

### 6.3 날씨

`--with-weather`를 사용하면 STTN의 승차 정류장 좌표와 `board_datetime`을 기준으로
Open-Meteo Historical Weather API의 시간별 WMO 코드를 조회합니다. 좌표는 0.1도 격자로
묶고 응답은 `data-pipeline/cache`에 저장해 같은 격자·날짜를 다시 호출하지 않습니다.
WMO 코드는 `맑음`, `구름많음`, `흐림`, `안개`, `비`, `눈`, `뇌우`로 변환합니다.

2024년 4월 1일 서비스 일자 파일럿은 실제 승차 정류장 2,820개가 13개 격자로 묶였고,
다음 날 새벽 운행을 포함한 2일의 날씨를 연결해 NULL 0건을 확인했습니다. 날씨 외 모든
출력 컬럼은 날씨 미사용 파일럿과 동일했습니다.
